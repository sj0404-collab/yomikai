# Отчёт качества — Yomikai v1.9.158: почему не появилась плавающая кнопка

## Назначение

Читатель сообщил: Служба доступности после v1.9.157 включается, но плавающая
кнопка оверлея не появляется «нигде» — ни поверх своих настроек, ни поверх
чужих приложений. По уведомлению «OCR-кнопка» из шторки видно, что сервис
жив и поработал, а значит право «Показ поверх других приложений» выдано. При
этом при запуске мелькал тост «Нет разрешения показывать поверх приложений».

Причина в том, что этот тост сопровождал **любой** сбой `WindowManager.addView`,
а не только отказ в праве. Настоящее исключение нигде не показывалось и не
попадало в лог, поэтому по отчёту нельзя было понять, что реально упало.
Хуже того, `root` выставлялся ДО `addView`, поэтому при провале сервис с
`START_STICKY` перезапускался с `root != null` и больше никогда не пытался
собрать окно заново — кнопка исчезала «навсегда».

## Состав изменений

| Область | Что изменено | Ожидаемый эффект |
|---|---|---|
| Диагностика окна | `addPanelWindow()`: класс и текст исключения пишутся в лог и попадают в тост | Видно настоящую причину сбоя, а не всегда «нет разрешения» |
| Состояние окна | `root`/`params` обнуляются при окончательном провале `addView` | `START_STICKY`-перезапуск снова пробует собрать кнопку, а не остаётся без окна |
| Повтор | До двух повторов `addView` с паузой 400 мс, если право выдано | Сервис успевает встать в foreground — окно добавляется со второго раза |
| Право | При окончательном провале, если `canDrawOverlays` уже false, открывается экран «Показ поверх других приложений» | Понятный путь, если право всё-таки отозвано |
| Foreground | `ensureForeground()` логирует сбой `startForeground` с типом | Видно, если сервис не смог стать foreground и из-за этого не даёт окно |

## Проверки

- Локальная компиляция `:app:compileDebugKotlin` — `BUILD SUCCESSFUL`.
- Полная сборка и релиз — workflow `Release` по тегу `v1.9.158` (arm64-v8a,
  подписанный APK).

## One build — one APK

Сборка выполняется только workflow `Release` по тегу `v1.9.158`. Подписанный
arm64-v8a APK — в Releases.

## Ручная проверка

1. В настройках оверлея нажать «Запустить».
2. Уйти в другое приложение (или на домашний экран) — кнопка должна появиться
   у края экрана.
3. Если кнопки нет и появляется тост «Не удалось показать кнопку — …» — в
   тексте тоста будет класс и сообщение настоящего исключения. Именно этот
   текст нужен, чтобы починить причину окончательно.
4. То же исключение пишется в лог с тегом `OcrOverlayService`.

## Известные ограничения

- **Причина сбоя `addView` пока не устранена окончательно** — этой сборкой она
  становится видимой. Вероятные варианты: право «Показ поверх других
  приложений» фактически не выдано (тогда помогает повторный запрос) или
  сервис не успел стать foreground (тогда помогает повтор `addView`).
- **Служба доступности у APK не из магазина блокируется системой.** Снять
  блокировку можно только вручную: «О приложении» → ⋮ → «Разрешить
  ограниченные настройки». Код это обойти не может — он только ведёт туда.
- **Картинка кадра в окне не показывается** — только распознанный текст в
  бабле.
- **Точность распознавания игровых шрифтов не проверена.**
