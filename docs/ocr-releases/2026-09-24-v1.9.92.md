# Отчёт качества — Yomihon v1.9.92: скриншоты с картинкой, добор реального текста при онлайн-OCR и более быстрый скан

## Назначение

Этот отчёт сопровождает единственную разрешённую подписанную release-сборку
`v1.9.92`. Релиз закрывает жалобу пользователя: онлайн-OCR на страницах манхвы
(Remanga) зачитывал мелкую ватермарку «Читай раньше всех на Remanga» вместо
крупной реплики, авточтение «висло» и не двигалось с места, а вкладка
«Скриншоты» хранила только текст с координатами.

## Состав изменений

| Область | Что изменено | Ожидаемый эффект |
|---|---|---|
| Настоящие скриншоты | `OcrScreenshotBuffer` + `OcrScreenshotEntry`: запись теперь хранит и JPEG-кадр (`filesDir/screenshots_images/<id>.jpg`); `AutoReadEngine.readFrame` и `captureInstantScreenshot` пишут его до `recycle()` кадра. При переполнении кольцевого буфера, очистке и очистке главы файлы удаляются вместе с записью. `diskSizeBytes()` учитывает картинки. | Во вкладке «Скриншоты» — настоящие изображения страниц с оверлеем распознанных регионов, а не только «текст по координатам». |
| Кто распознал | `engineUsed` в записях теперь берётся из `result.ocrModel` (движок, который реально ответил, включая сработавший фолбэк), а не из настройки `prefs.ocrModel()`. | Белая точка: на карточке скриншота и на деталях видно реальный движок распознавания. |
| Добор текста при онлайн-OCR | `AutoReadEngine.readFrame`: если онлайн-движок (Glens/ZenFree/Google/OpenRouter/OwOCR) вернул меньше 3 осмысленных строк (типичный случай — «видна только ватермарка»), кадр дополнительно разбирается локально (YOLO-баллоны + Cyrillic OCR) и результат доклеивается к репликам онлайн-движка. Дубли между «онлайн-текстом» и добором режутся штатным фильтром истории. | Крупные реплики манхвы не пропадают, даже если AI-модель их не увидела; ватермарка перестаёт быть единственным текстом страницы. |
| Скорость сканирования | Таймаут кадра OCR снижен с 45 до 25 секунд (`OCR_FRAME_TIMEOUT_MS`), применён и к «сканировать и читать» (`ReaderViewModel.autoScanAndSpeak`, раньше таймаута не было вовсе — онлайн-движок мог блокировать авточтение бесконечно). По таймауту кадр считается пустым и листание продолжается. | «Зависший» онлайн-OCR больше не держит авточиталку; скан не стоит на месте. |
| UI галереи | `ScreenshotTab.ScreenshotCard`: миниатюра JPEG-кадра (72×96dp) + движок в заголовке. `ScreenshotDetailScreen.RegionOverlay`: реальный кадр (coil3, пропорции сохранены, регионы ложатся точно на текст) вместо синтетической сетки; сетка-заглушка остаётся только для старых записей без JPEG. | Привычная картинка страницы с подсветкой распознанного. |

## Положительные качества

Для онлайн-движков 99% страниц по-прежнему распознаются в один проход (полная
видимая область одной моделью) — добор баллонов включается только на
подозрительно пустых кадрах (<3 строк), поэтому цена локального разбора платится
лишь там, где онлайн-текст реально пропущен.

Скриншоты не «съедают» память: JPEG пишется c достигшего ресайзинга кадра
(длинная сторона 1600px, качество 78) и удаляется автоматически — при вытеснении
из кольцевого буфера, при ручной очистке и при очистке главы.

Атрибуция движка честная: если Glens упал и сработал фолбэк на Cyrillic, на
скриншоте будет написано именно «cyrillic», а не «glens».

Таймаут 25 с — компромисс: локальный движок при первом запуске (загрузка
модели) обычно укладывается, а «вечный» онлайн-запрос режется строго.

## Отрицательные качества и ограничения

Добор баллонов добавляет YOLO-проход + пофрагментный Cyrillic-OCR на кадрах, где
онлайн-движок вернул мало строк. На странице с 1–2 настоящими репликами это
стоит дополнительной локальной работы (сотые доли секунды для YOLO, суммарно
несколько секунд на распознавание кронов) — это плата за то, что реплика не
пропущена.

Размер записи скриншота вырос: текст (~1–5 KB) + JPEG (~100–400 KB на 1600px).
При лимите 50 записей хранилище занимает до ~20 МБ. Лимит по-прежнему
настраивается в dev-панели.

JPEG-кадр — это кадр авточтения (то, что показывает экран в момент скана), а не
оригинал страницы из кеша: пропорции и содержимое соответствуют моменту реплик.

## Обязательные проверки финального runner

| Проверка | Требование |
|---|---|
| `verifySqlDelightMigration` | Успешно (прогнано локально: `BUILD SUCCESSFUL`). |
| `:data:testDebugUnitTest` | Успешно (прогнано локально). |
| `:app:testDebugUnitTest` | Успешно, включая `AutoReadEngineCleanTest` и `OcrRegionTapTest` (прогнано локально). |
| `:app:compileDebugKotlin` | Успешно (прогнано локально с доступным Android SDK). |
| `assembleRelease -Penable-updater` | Собран только подписанный release-вариант на GitHub Actions runner. |
| Ровно один APK | `app-arm64-v8a-release.apk`, иначе шаг Assert падает. |
| Версия внутри APK | `versionName` == тегу без `v` (`1.9.92`), `versionCode` >= 10908. |
| SHA-256 и размер | В логе, в описании релиза и в этом отчёте. |

## One build — one APK

Сборка выполняется только workflow `Release` по тегу `v*`; `Tests`
(`build.yml`) APK не собирает. Этот кандидат проходит по тому же правилу:
коммит на `main` → тег `v1.9.92` → один подписанный APK + этот отчёт.

## Ручная проверка на устройстве после получения APK

1. Открыть онлайн-главу с ватермарками (например, Remanga) и включить
   авточтение с онлайн-движком: вместо одной ватермарки должны зачитываться и
   настоящие крупные реплики страницы; авточтение не «виснет» на 45 секунд и
   листает дальше.
2. Во вкладке «Скриншоты»: карточки содержат миниатюру настоящего кадра, на
   детальном экране изображение с рамками регионов; в заголовке карточки —
   реальный движок OCR.
3. «Сканировать и читать» не блокируется дольше 25 секунд при недоступном
   онлайн-движке (показывается «текст не найден» и работа продолжается).
4. Очистка (кнопка в вкладке, очистка главы, вытеснение из кольцевого буфера)
   удаляет и файлы JPEG: размер хранилища не растёт бесконечно.
