# Отчёт качества — Yomihon v1.9.95: кнопки-варианты в AI-чате

## Назначение

Релиз закрывает единственное «обещанное, но не сделанное» место в AI-чате: системный промпт агента предлагал модели заканчивать ответ строками `[[Текст варианта]]` и обещал «кнопки под сообщением», но разобранный `AgentReply.choices` нигде в UI не показывался. Теперь варианты действий — кнопки, а разметка из текста ответа убирается.

## Состав изменений

| Область | Что изменено | Ожидаемый эффект |
|---|---|---|
| Разбор вариантов | Инлайн-код разбора `[[...]]` в `AiAgent.run()` вынесен в `AiAgent.parseChoices` / `AiAgent.stripChoices`. | Разметка из текста ответа убирается, тексты вариантов сохраняются; разбор тестируем отдельно от сети и Android. |
| История | В `AiHistoryManager.Msg` добавлено поле `choices` (дефолт — пустой список). | Варианты переживают перезаход в чат; старые файлы `ai_history_*.json` без поля читаются без ошибок (тест). |
| UI | Под ответом AI рендерятся кнопки вариантов; тап отправляет текст варианта как новую реплику (через тот же `send`). | Пользователь выбирает продолжение одним тапом, не перепечатывая текст. |

- `:app:testDebugUnitTest --tests "eu.kanade.tachiyomi.data.ai.*"` — успешно: `AiChoicesTest` ×5 (до 4 вариантов, пустой список, очистка разметки, round-trip сериализации, совместимость со старыми файлами истории) плюс регрессии `AiBackendsTest`, `AiProvidersTest`, `AiReaderToolsTest`, `AiWorkspacePathsTest`.

Сборка выполняется только workflow `Release` по тегу `v1.9.95`. Ожидается один подписанный arm64-v8a APK; версия и SHA-256 фиксируются runner-ом в отчёте и release.

## Ручная проверка

1. В AI-чате открытой главы спросить «что можно сделать дальше?» — при ответе модели с вариантами `[[...]]` под сообщением появляются кнопки.
2. Тап по кнопке отправляет текст варианта новой репликой, чат продолжается без перепечатывания.
3. Выйти из главы и вернуться — варианты на месте в истории.
4. Ответ, который заканчивается вариантами, показывает чистый текст без `[[...]]`.
