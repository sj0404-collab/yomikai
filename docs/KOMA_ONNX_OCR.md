# KOMA-путь кириллицы: что это и куда встроено

Документ отвечает на два вопроса: **что именно делает KOMA** (чтобы не
переизобретать) и **куда это легло в Yomikai** (файл → строка → зачем).

## 1. Что делает KOMA

KOMA — отдельная читалка на Kotlin/Compose, 939 строк Kotlin на всё
приложение. OCR у неё на двух путях:

| Письменность | Путь |
| :--- | :--- |
| латиница / японский / китайский / корейский | ML Kit `text-recognition` (модели внутри APK) |
| кириллица | ONNX Runtime: детектор PP-OCRv4 + CTC-распознаватель East Slavic PP-OCRv5 |

Кириллический путь — это один файл `data/OcrEngine.kt` (169 строк) и три
ассета: `models/detection.onnx` (4.7 МБ), `models/cyrillic.onnx` (7.9 МБ),
`models/cyrillic.txt` (словарь, 1.6 КБ).

Пайплайн ровно такой:

1. **Плитки.** Страница выше 2800 px режется на плитки по 1800 px с
   перекрытием 160 px. Дубли на стыке отбрасываются по тексту и близости
   верхней границы (< 0.015 в нормализованных координатах).
2. **Детектор.** Картинка масштабируется так, чтобы максимум стороны был
   ≤ 960 и кратен 32; нормализация ImageNet (mean `0.485/0.456/0.406`,
   std `0.229/0.224/0.225`). Выход — карта вероятностей.
3. **Компоненты связности.** BFS по порогу `0.3`, отбраковка: меньше 6
   пикселей, средний балл компонента < `0.5`, ширина/высота < 2 px. Бокс
   расширяется на `max(2, w*h*1.5 / (2*(w+h)))` — это и есть та «рамка в
   аккурат по тексту», которая видна на скриншотах.
4. **Кроп и поворот.** Если кроп выше, чем в 1.8 раза шире, — поворот на
   90° (вертикальные надписи).
5. **Распознаватель.** Вход `3×48×W`, W = 48·w/h, зажат в 8..960,
   добит нулями до минимум 320 (модель ждёт фиксированную минимальную
   ширину). Нормализация `(x/255 − 0.5)/0.5`.
6. **CTC-жадный декодер.** Словарь = `[""] + строки cyrillic.txt + [" "]`
   (индекс 0 — blank, последний — пробел). Повторы подряд схлопываются.
   Балл строки — среднее «сырое» значение логита на символ; строки со
   средним ≤ `0.25` выбрасываются.
7. **Порядок.** Сортировка по `(top*80).toInt()`, затем по `left`.

Почему это работает лучше прежнего пути Yomikai: там LiteRT-модели
PP-OCRv3 + PP-OCRv5-верификатор + «спасательные» проходы (сегментация слов,
полосатая нарезка, повторное распознавание кропов). Каждый эшелон — это
шанс испортить чистую строку и лишние миллисекунды. У KOMA один детектор и
один распознаватель: меньше решений — меньше способов ошибиться.

**Честные ограничения KOMA** (из README_RU.md и по коду):

- пробелы между словами не восстанавливаются — их «склеивает» CTC; это и
  есть тот мелкий косяк, который видно на скриншотах (`ОНЁ`, `НЕВРЕДИМЫМ`);
- порядок блоков — эвристика, а не анализ панелей;
- детектор ищет текст по всей странице, а не только в облачках;
- модели только кириллица; остальные языки — ML Kit.

## 2. Куда это встроено в Yomikai

Новые файлы:

| Файл | Что внутри |
| :--- | :--- |
| `data/src/main/java/mihon/data/ocr/KomaOnnxOcrEngine.kt` | Сам движок: `OcrEngine`, `LineOcrEngine`, `detectRegions()`, `recognizeRegions()`. Логика 1:1 из KOMA, с модернизациями под Yomikai: `OcrException` вместо `error()`, мьютекс, отмена через `withContext`, `OcrBoxGeometry.normalize()` для рамок. |
| `data/src/main/java/mihon/data/ocr/KomaDetOcrEngine.kt` | Адаптер `DetOcrEngine` → тот же ONNX-детектор, без второй копии модели в памяти. |

Правки в существующих файлах:

| Файл | Правка |
| :--- | :--- |
| `gradle/libs.versions.toml` | `onnxruntime = "1.22.0"`, `onnxruntime-android`. |
| `data/build.gradle.kts` | `implementation(libs.onnxruntime.android)`. |
| `mihon/data/ocr/OcrModelFiles.kt` | Три пути в `flatNames`: `koma_ocr/det.onnx` → `koma_det.onnx`, `koma_ocr/rec.onnx` → `koma_rec.onnx`, `koma_ocr/dict.txt` → `koma_dict.txt`. |
| `mihon/data/ocr/OcrRepositoryImpl.kt` | Настройка `pref_ocr_use_koma_onnx` (по умолчанию `false`), поле `komaEngine`, ветка в `engineFor(CYRILLIC)`, ветка в `detectionEngine()`, helper `komaModelsInstalled()`, закрытие в `closeEngines()`. |

Ключевое решение: **это не замена движка, а второй backend кириллицы**.
`OcrModel.CYRILLIC` остаётся тем же пунктом меню, но при включённой
настройке `pref_ocr_use_koma_onnx` внутри выбирается ONNX-движок. Так
откат — один чекбокс, а весь остальной код (кэш, сканы глав, очередь,
оверлей, TTS) не знает, какой бэкенд под ним работает.

Что **не** пришлось трогать: `OcrModel`, `OcrPlugins`, интерфейсы
`OcrEngine`/`LineOcrEngine`/`DetOcrEngine`, кэш `OcrCacheStore`, сканер
главы, Ui. Enum и реестр плагинов остаются прежними — иначе пришлось бы
править все `when` по `OcrModel` в трёх модулях.

## 3. Модели

В APK они не входят (правило проекта: APK без локальных моделей). Нужно
положить три файла в `Android/data/app.yomihon/files/ocr_models/`:

```
koma_det.onnx     # detection.onnx из KOMA, 4.7 МБ
koma_rec.onnx     # cyrillic.onnx из KOMA, 7.9 МБ
koma_dict.txt     # cyrillic.txt из KOMA, 1.6 КБ
```

Они уже вынуты из `KOMA-source.zip` и лежат рядом с этим репозиторием в
`koma_models/`. Для сборки пакета моделей в `OcrModelDownloader` достаточно
добавить ещё один `NOTIF_IDS`-id и те же три URL.

## 4. Как проверить

1. Скачать/положить модели, включить `pref_ocr_use_koma_onnx`.
2. Открыть главу с кириллицей → «Текст страницы». Ожидаемо: рамки совпадают
   с облачками, текст по строкам, без латинских вкраплений.
3. Сравнить с прежним путём (настройка выключена) на тех же трёх страницах:
   время в журнале OCR (`AiConsole.ocr` пишет миллисекунды) и число ошибок.
4. Негативные кейсы из KOMA: пустой баллон `?!` — движок не должен ничего
   вернуть; корейский звуковой эффект — не должен превратиться в «русское
   слово» (у KOMA именно это и ломало страницу 2).

## 5. Риски и чего этот коммит не делает

- **Не проверено на устройстве**: здесь нет Android SDK и телефона, код
  собран «по мотивам» KOMA, компиляцию подтверждает CI.
- **Размер APK**: `onnxruntime-android` добавляет нативные библиотеки
  (~10–15 МБ на ABI). Если это критично — `abiFilters` только под arm64-v8a
  либо конвертация обеих ONNX-моделей в TFLite и работа через уже
  подключённый LiteRT.
- **Пробелы**: пробелы по-прежнему не восстанавливаются. Следующий шаг —
  прогнать текст через существующий `OcrTextCleaner`/`textPostprocessor` и
  словарь словоформ (он уже есть: `RuWordListPart*`), прежде чем отдавать
  строку в TTS.
- **UI-настройки**: чекбокс `pref_ocr_use_koma_onnx` пока живёт только в
  preference-сторе; экран настроек OCR — следующий шаг.

## 6. Настройки и релиз

- Переключатель: «Настройки → Распознавание → Кириллица → Движок KOMA
  (ONNX): PP-OCRv4 + PP-OCRv5». Ключ `pref_ocr_use_koma_onnx`, читается через
  `OcrPreferences.komaOnnxCyrillic()` — один источник и для движка, и для UI.
- Сборка APK — штатный workflow `Release` по тегу `v*` (arm64-v8a, ключ из
  secrets). Ветка `feat/koma-onnx-ocr` содержит только код и отчёт
  `docs/ocr-releases/CURRENT.md`, который CI вкладывает в релиз.
