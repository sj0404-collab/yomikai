# Оверлей: чтение рамки над чужим приложением

Отдельная ветка: `feat/overlay-frame-reader`. Основная работа — в `main`,
эта ветка держит её отдельной линией, чтобы потеря или подмена основной
ветки не забрала её вместе с собой.

Текущий статус: `v1.9.113` собран, CI `36559586249` — `success`.

## Что здесь реализовано

Оверлей поверх чужого приложения читает область сам: снимает кадр через
MediaProjection, распознаёт, озвучивает и листает приложение своим жестом.

| Файл | Роль |
|---|---|
| `OcrCaptureActivity.kt` | Прозрачная activity: только спрашивает разрешение на захват и отдаёт его сервису. Из сервиса системный диалог MediaProjection поднять нельзя. |
| `OverlayCaptureEngine.kt` | Захват через VirtualDisplay + ImageReader, вырезание рамки, защита от half-initialized состояния. |
| `OverlayGestureService.kt` | AccessibilityService ровно для `dispatchGesture`. События не читает, узлы не обходит, ничего не выполняет. Выключена по умолчанию. |
| `OverlayAutoReader.kt` | Цикл «кадр → OCR → озвучка → ожидание конца речи → свайп», остановка на одинаковом кадре. |
| `OcrOverlayService.kt` | Панель, рамка области, круглая кнопка в углу, вертикальное меню. |

## Обязательные условия работы

- **Разрешение «Показ поверх других приложений»** — иначе окно не появится.
- **Служба доступности** — без неё листать чужое приложение нечем: свой жест
  отправлять нечем. Пока выключена, чтение ждёт и говорит об этом, а не
  молча замирает после первой реплики.
- **Область рамки** — задаётся кнопкой ✏ в настройках оверлея.

## Решения, которые стоит знать перед правкой

**Жест проверяется по ответу системы.** `dispatchGesture` возвращает лишь
«жест отправлен». Если бы этого хватало, чтение замолкало бы на первом
отказе — так и было. Теперь `swipeAndAwait` ждёт `GestureResultCallback`,
при отказе повторяет жест, а если приложение его игнорирует — свайпает
длиннее и из другой точки.

**Фоновой работе достаётся своя копия кадра.** `AutoReadEngine` отдавал в фон
исходный битмап, а вызывающий переиспользовал его сразу: `getPixels` по
переиспользованному битмапу ронял процесс сразу после «Скриншот сохранён».

**`mediaProjection` обязателен в типах foreground service.** На Android 14+
без него (и без `FOREGROUND_SERVICE_MEDIA_PROJECTION`) вызов
`getMediaProjection()` падает в SecurityException — захват не начинается.

**Трекеры прощают неполные ответы.** У `SeriesDto`, `VolumeDto` и
`HKPagination` поля без значения по умолчанию валили разбор всего ответа, а
в общем `Json` добавлен `coerceInputValues`.

**Движок оверлея выбирается явно.** `recognizeText(image, model)`: без явной
модели распознавание уходило в движок читалки, и переключатель «свой движок»
менял только подпись на кнопке.

## Чего здесь нет

- Показ самой страницы в рамке — только распознанный текст в бабле.
- Чтение книг (только то, что видно на экране поверх приложения).
- Оверлей не умеет листать без Службы доступности, и обойти это нельзя.
