# Прототип OpenCode-агента — список будущих правок

Зафиксировано по результатам первого теста APK v1.9.81. Ветка-прототип:
`prototype-opencode-agent` (файлы агента), `opencode.yml` — в `main` (GitHub
диспатчит только воркфлоу default-ветки).

## 1. Запуск «как в оригинале»: сначала сайт, агент выбирается внутри

Сейчас `opencode.yml` сам поднимает `opencode serve` + oc-gateway + npm-hub
и публикует `url`=чат, `terminal`=npm-hub. В оригинале (zen-panel) порядок
другой: открывается **сам сайт/хаб**, и уже внутри пользователь сам выбирает
и запускает нужного агента (opencode и т.п.) из лаунчера хаба.

Правка:
- воркфлоу поднимает только **npm-hub** (с его дашбордом и лаунчером агентов);
- `opencode serve` не форсируется автоматически — агент стартует по кнопке
  внутри хаба;
- endpoint-артефакт несёт `terminal` (npm-hub), а `url` не нужен принудительно.

## 2. Сайт хранить не в приложении, а на GitHub Pages

Сейчас статика npm-hub (`npm-hub/public/`) живёт в репозитории и отдаётся
ранером. Нужно вынести сайт на GitHub Pages (отдельная ветка/workflow деплоя),
а в APK не таскать статику. Приложение открывает Pages-URL хаба; API/терминал
идут через туннель ранера.

## 3. Сайт отрисовывается чёрным

При открытии WebView весь сайт был чёрным. Диагностировать:
- фон WebView задан чёрным и, вероятно, CSS/JS npm-hub не подгрузились
  (проверить `onPageFinished`, консоль, URL `terminal` + `/m`);
- проверить CSP/X-Frame-Options и корректность пути статики на Pages.

## 4. Вшивать сайт напрямую в приложение (вкладки), а не отдельным WebView

Хочется, чтобы хаб не открывался одним полноэкранным WebView, а был встроен
в приложение: нативные Compose-вкладки (Чат / Терминал / Файлы / Дашборд),
фиксы багов внутри, единый UI. Вкладка AI становится обёрткой с нативными
элементами поверх туннельного контента.

## 5. БАГ: при смене вкладки WebView закрывается и не открывается снова

Симптом: переключился на другую вкладку приложения — хаб скрылся; вернуться
можно было только запустив ранер заново (с нуля).

Причина: активная сессия живёт в локальном `remember { mutableStateOf(...) }`
внутри `Content()`. При уходе со вкладки композиция пересоздаётся, состояние
сбрасывается → экран показывает «Запустить» снова, даже если ранер жив.

Правка: хранить активную сессию в объекте `AiChatTab` (как
`hubStatusFlow`/`hubStartingFlow`) и при возврате на вкладку автоматически
переоткрывать WebView по сохранённой сессии. Сессии и так сохраняются на
телефоне (`RunnerLlm.listSessions`); надо лишь восстанавливать активную.
