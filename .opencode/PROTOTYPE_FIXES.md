# Прототип OpenCode-агента — правки (v1.9.82+)

Статус по результатам теста APK v1.9.81. Ветка-прототип:
`prototype-opencode-agent` (файлы агента), `opencode.yml` — в `main` (GitHub
диспатчит только воркфлоу default-ветки).

## ✅ 1. Запуск «как в оригинале»: сначала сайт, агент выбирается внутри — СДЕЛАНО

`opencode.yml` больше НЕ форсирует `opencode serve` + oc-gateway. Ранер
поднимает только **npm-hub** (дашборд, терминал, файлы, git, инструменты)
и туннель. Endpoint: `url` = корень хаба, `terminal` = хаб `/m`. Нужного
CLI-агента пользователь выбирает/устанавливает сам внутри хаба (вкладка
«Инструменты» или терминал) — как в оригинальном zen-panel.

Список агентов в хабе ужат до реально работающих без платных ключей:
`opencode`, `aish` (офлайн GGUF), `deepseek-harness` (`dsh`, DeepSeek Harness —
добавлен по просьбе). Остальные выпилены: им нужен платный ключ (claude-code,
codex, copilot, gemini, qwen, mistral…) или нестабильная установка (aider,
goose, openhands…).

## 2. Сайт хранить не в приложении, а на GitHub Pages — РЕШЕНИЕ ОТЛОЖЕНО

npm-hub — это Node-сервер с API (`/api/*`) и терминалом (WebSocket xterm),
фронтенд зовёт API по относительным путям (`fetch('/api/tools')`). Дословный
перенос статики на GitHub Pages (другой origin) сломает все API-вызовы и
терминал. Сайт и так не живёт в APK — приложение просто открывает WebView на
туннель ранера. Рекомендация: оставить npm-hub единым сервером за облачным
туннелем. Если всё же хочется Pages — нужен отдельный «парадный» лендинг, а
не живой хаб (без API он бесполезен).

## ✅ 3. Сайт отрисовывается чёрным — ИСПРАВЛЕНО (дефенсивно)

- фон WebView был `BLACK` — при медленном туннеле выглядел как мёртвый экран;
  теперь `WHITE` + `MIXED_CONTENT_ALWAYS_ALLOW`;
- добавлен экран загрузки («подключение…») и обработка `onReceivedError`
  с кнопкой повтора, вместо пустого чёрного листа;
- `onReceivedHttpAuthRequest`/`destroy`/`reload` обёрнуты в `runCatching` —
  APK не крашится «от каждого чиха».

## 4. Вшивать сайт напрямую в приложение (вкладки) — ПОЗЖЕ

Хаб открывается внутри той же вкладки AI (WebView + нативные управляющие
элементы поверх). Отдельный набор нативных Compose-вкладок (Чат/Терминал/
Файлы) поверх самого хаба дублирует его внутреннюю навигацию — отложено до
вопросов пользователя про UX.

## ✅ 5. БАГ: при смене вкладки WebView закрывается и не открывается — ИСПРАВЛЕНО

Активная сессия перенесена из локального `remember` в объект `AiChatTab`
(`hubSessionFlow`). Переключение вкладки больше не сбрасывает открытый хаб;
возврат на вкладку показывает сайт снова (watch из `collectAsState`),
перезапускать ранер не нужно.

## ✅ 6. APK не крашится «от каждого чиха» — СДЕЛАНО

WebView-создание, reload/auth/destroy, чтение и удаление сессий, запуск
ранера — везде `runCatching`/`getOrElse` с выводом ошибки в UI, а не падением.
